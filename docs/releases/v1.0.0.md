# v1.0.0 · g2rain-member-app 首个稳定版

G2rain（谷雨）是面向企业的开源智能体平台，连接模型、知识与业务工具，让智能体在明确的身份和权限边界内执行任务。平台目前具备应用开发、部署与使用的基础；智能体平台与智能客服已开发完成并开源，交易、订阅、计量计费等商业化能力仍处于规划设计中。`g2rain-member-app` 只是该平台中的 Vue 3 会员业务微前端应用模板：它交付独立/qiankun 集成运行、SSO 接线、资源路由、权限 UI、国际化、Mock、代码与资源配置生成，以及 OpenResty 静态托管与代理。它不提供平台整体能力，也不替代 IAM 的认证、Gateway 的入口校验或后端服务的最终授权。

## 构建、镜像与内容

- 项目版本：`1.0.0`（`package.json` 与 `docs/project.yaml`）；许可证：根目录 Apache License 2.0，OCI 许可证标签为 `Apache-2.0`。
- 构建要求：Node.js `>=22` 和 npm；`npm ci && npm run build` 执行 TypeScript 类型检查与 Vite 生产构建。本仓没有独立 unit、E2E 或 lint 脚本。
- 镜像：`ghcr.io/g2rain/g2rain-member-app:1.0.0` 与 `ghcr.io/g2rain/g2rain-member-app:sha-<完整提交 SHA>`；不会发布或更新 `latest`。最终镜像使用根目录 Dockerfile 的 Node 22 Alpine 构建阶段和 OpenResty Alpine 运行阶段，入口为 `/docker-entrypoint.sh`，声明端口 `8080`；OCI source、title、version、revision 和 licenses 指向本仓及本版本。
- 最终镜像包含 Vite `dist/`、Lua 签名代码、Nginx 模板、入口脚本和离线构建的 luaossl；不复制仓库源代码、文档、`.git` 或 `lua/keys/`。`lua/keys/` 在镜像中只创建为空目录，生产密钥必须由部署环境以 Secret/受控 Volume 挂载注入。

## 发布顺序与 GHCR

1. 按 `feature/* → develop → main` 将版本、工作流和本说明合入 `main`，并在该提交完成验证。
2. 在已验证的 main 提交创建并推送 `v1.0.0`。工作流只接受精确的稳定 tag，校验 tag 提交在 `origin/main` 历史、`package.json` 版本一致且本文件非空，然后运行 `npm ci` 和 `npm run build`。
3. 工作流以 `GITHUB_TOKEN` 推送版本和完整 SHA 两个标签；只有两个推送均成功才显示发布摘要。不会创建 GitHub Release、部署服务或更新 `latest`。
4. 首次成功推送后，如需匿名拉取，在 GitHub Packages 的 **Package settings → Change visibility → Public** 将 `g2rain-member-app` 设为 Public；组织管理员禁止修改时联系管理员。已有包可能仍须在 **Package settings → Actions access** 授予 `g2rain/g2rain-member-app` 写权限；GHCR `denied` 时优先检查该项和组织 Packages 策略。

公开后可匿名拉取：`docker pull ghcr.io/g2rain/g2rain-member-app:1.0.0`。私有包需要具有 `read:packages` 权限的凭据。

## 安全、限制与验证状态

生产环境将 `private-key.der`、`public-key.der`、`iam-key-id.txt`（可选）和 `iam-public-key.pem`（可选）挂载到 `/usr/local/openresty/nginx/lua/keys/`；不要将生产 Token、私钥、IAM 密钥或私有地址烘焙进镜像。构建期 `VITE_*` 和运行时 `env-config.js` 对浏览器可见，不能承载 Secret。`.dockerignore` 会排除已跟踪的 `.env`、Markdown 文档和 `lua/keys/README.md`，但 `.env.production` 会进入构建阶段供 Vite 读取；它目前只含公开占位配置，且不会被复制到最终镜像。维护者仍须在首次公开前复核它和构建日志，确认没有新增凭据；Docker 忽略规则不能治理 Git 历史或已进入产物的内容。

本发布准备不声称 Docker 构建、容器启动、GHCR 推送、匿名拉取、在线演示或实际部署已经完成。自动化的真实范围是依赖安装、TypeScript 类型检查和 Vite 构建；它不证明浏览器 E2E、qiankun 双模式、SSO/IAM/Gateway 联调、Lua 密钥挂载、镜像运行或生产部署。OpenResty 运行时默认 `SERVER_PORT=80`，虽然镜像声明 `8080`，部署应显式设定 `SERVER_PORT=8080`，并保持 `VITE_CONTEXT_PATH`、`CONTEXT_PATH` 与 main-shell 配置一致。
